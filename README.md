# claude-plugins-coldlogic

The `coldlogic-plugins` marketplace, holding one plugin: `coldlogic@coldlogic-plugins`.

The plugin does three things:

- **Bundles the plugins every project uses** as `dependencies` in `plugin.json`. Enabling `coldlogic` in a project installs the whole set at project scope.
- **Prints the shared conventions** (`conventions/*.md`) into every session through a SessionStart hook.
- **Flags a stale setup** at session start: a `coldlogic-devenv` lock behind its remote, OpenSpec skills generated by another CLI version, and auto-installed plugins nothing needs.

Projects never install it by hand. The [coldlogic-devenv](https://github.com/coldlogicsolutions/coldlogic-devenv) module registers the marketplace with `autoUpdate: true` and enables the plugin in each project's generated `.claude/settings.json`. Nothing goes in user settings, so third-party repos get none of it.

## Changing the plugin set

- **Add a plugin everywhere:** add a line to `dependencies`. Each project picks it up at its next session.
- **Remove one everywhere:** delete the line, then run `claude plugin prune` once the change ships. The staleness hook reminds you.
- **Only some projects:** enable it in that devenv profile's `enabledPlugins` instead.
- A dependency from a new marketplace also needs that marketplace in `allowCrossMarketplaceDependenciesOn`, and in the module's `extraKnownMarketplaces`.

## Developing

```bash
claude --plugin-dir ./plugins/coldlogic
scripts/validate.sh   # validate --strict, except the deliberately missing version
```

Add code here only for something Claude Code, an official plugin and the devenv module can't already do.
