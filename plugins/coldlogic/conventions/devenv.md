# Dev environment

- Every tool runs through the project's devenv shell: `devenv shell --quiet -- <cmd>`. Never `nix develop`.
- System dependencies and environment setup go in `devenv.nix`, not in ad-hoc installs.
- `scripts/check.sh` is the gate. It must pass before committing. Do not commit on a red gate, and do not weaken a test to make it pass: fix the code or flag the spec.
- Never pipe the gate through something that hides its exit status (`scripts/check.sh | tail` reports `tail`'s status). Check the exit status directly.
- `.claude/settings.json` is generated by devenv and is a read-only symlink. Change settings in Nix (`claude.code.*` or the `files` entry in `devenv.nix`), never by editing that file.

## When a command is blocked

- The sandbox, the deny rules and the coldlogic guard hook are deliberate. A blocked command is never retried unsandboxed, reworded to get past a rule, or run another way that does the same thing.
- If the command is legitimate and the session needs it, propose the permission change through a PR: a shared need (a tool every project runs, a host every build fetches from) goes in `coldlogic-devenv`'s `devenv.nix` or the language profile, and a project's own in its `devenv.nix` (`claude.code.permissions.rules`, or `files."${config.claude.code.settingsPath}".json.sandbox`). Say in the PR what was blocked, why it's needed, and why the narrowest rule that allows it is enough. Then carry on with other work, or stop and tell the user, until it merges.
- Anything else that gets in the way of the dev process (a permission prompt on routine work, a sandbox rule that breaks a normal git or build step, a tool missing from the shell, a hook misfiring) is raised as a GitHub issue in `coldlogicsolutions/coldlogic-devenv` as soon as it is hit: `gh-app issue create -R coldlogicsolutions/coldlogic-devenv --assignee derekjw …`, naming what was blocked, why the session needed it, and the narrowest fix. Not in the project's repo, not only in chat or memory. Link the issue in the session, then carry on. (Decided 2026-11-10.)
- Allow rules name the command run inside the devenv wrapper (`cargo test *`), not the wrapper: the guard applies them to what runs inside.
- `.env` and its variants can't be read or written. When a change needs a new variable, add it to `.env.example` and tell the user what the real file needs.
